主打
今天这一条，以及它在你身上的位置。
用户得到
不必逐个猜，四条一眼扫完，今天该看哪条一目了然。
我们传递

V4 · 通栏出血 + 卡片咬合

照片真的出血，文字有稳定底盘 —— 目前最推荐

照片突破页面左右留白做通栏出血（无圆角、无边框，375 全宽），信息不再压在照片上， 而是放进一张咬合上来 36px 的 cream 卡里。锚点全部落在照片上半区，不会被底部内容遮住。 用的正是 _base.scss 里预留的 .photo-hero--bleed + .photo-hero--hinge 组合。

解决了 V1 的什么
① 通栏无圆角 → 出血名副其实，不再是"小图贴卡里"； ② 文字进白卡 → 明暗可控，深浅照片都不影响可读； ③ 锚点在照片上半区 → 不会被行动条吃掉； ④ 信息量回到四层（编号 / 观察 / 建议 / 按钮）。
用户得到
照片够大够沉浸，同时每条建议都读得清、点得到。
我们传递
克制而有条理 —— 证据在上，结论在下，各归其位。
新鲜感怎么来
同 V1：日期徽标进状态位、锚点每天只亮一个、底部每天换一条。 另可把 V3 的序列进度条与「明天的预告」并进白卡。
视觉突破
照片层 + 卡层的咬合结构自带景深，是四版里唯一「既有冲击力又不牺牲可读性」的。
与现有设计系统同构：--bleed / --hinge / .card 都是现成语义类， 改动收敛在首页 hero，不动全局样式。
风险：通栏出血后照片左右无留白，微信下需确认圆角裁切只作用于卡片不作用于照片； 照片高度 352px 仍占屏较高，可降到 300~320px 让下方工具区多露一些。

每天的新鲜感，靠什么解决

报告是静态的（生成后不再变），所以「卡片每天一模一样」是必然的。新鲜感不能靠换配色、换布局这类假新鲜， 要来自「每天真的给你不一样的东西」——今日焦点轮转： 把静态的 findings 列表变成一个「每天只亮一盏灯」的序列。

要做的（真新鲜）

  • 确定性轮转：按日期取模选中当日焦点，绝不用随机 —— 刷新页面就变等于不可信。
  • 日期进入状态位：eyebrow 从「形象档案已就绪」换成「9月19日 · 今日焦点 02/4」。
  • 锚点分三档：今天亮 / 已看过淡 / 未到最淡，产生序列感与追更感。
  • 明天有预告：底部一行「明天：03 比例」，给出回来的理由。
  • 今日造型优先：有 today_plan 时直接切今日造型态（真正的每日内容，已有逻辑）。
  • 时段语境：早上指向「今天」，晚上指向「明天要穿什么」。

不做的（假新鲜 / 越红线）

  • 不做随机推荐 —— 每次刷新内容不同，会让人觉得系统在瞎猜。
  • 不做打卡 / 连续天数 —— 「已连续 3 天」是把产品焦虑转嫁给用户。
  • 不换配色换布局冒充更新 —— 内容没变，视觉换皮，两天就被识破。
  • 不写「你还有 3 个问题没解决」—— 清单式压迫，违反尊重表达红线。
  • 不用警示红标注锚点 —— 一律 cream / moss 中性色。
  • 不承诺「每天自动生成」—— 焦点来自已有 findings，不新增服务端承诺。
