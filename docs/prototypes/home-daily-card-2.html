A · 色卡类

色带 44px，横跨全宽
改了什么
色卡从 300px 大方块缩成 44px 高、横跨全宽的一条。它是"布样"，不是"画面"。4 个颜色一个不少，但不再假装自己撑得起一屏。
空出来的面积给了谁
给了标题。26px 的大字断成两行，标题本身就是视觉主体——这比任何色块都更有存在感，而且不需要素材。
排版的三个细节
① 眉标在左、编号在右且下沉 1px（不对称）；② 观察段左侧 2px moss 细线 + 13px 缩进，和标题分层；③ 原理块降到 11.5px 灰字，主动弱化。
信息层级
眉标 → 标题 → 观察 → 行动 → 色带 → 原理 → 动作，七层靠字号和字重区分，不靠色块。
这版没有一处是为了"填满"而存在。每个元素要么承载信息，要么承载节奏。

B · 原理类

一张图都不给
关键判断
这条的核心是认知，不是图像。硬配一张 CSS 肩线示意图，只会把"落肩吃掉肩"这么清晰的一句话，稀释成一张看不懂的图。
标题三行是刻意的
落肩 / 正在抹掉 / 你的肩线——最后一行用灰字，制造阅读的落点。这就是排版在承担视觉功能。
卡片会更矮
这一屏比 A 矮约 90px。我认为这是对的：内容少的日子就少占地方，比每天强撑一个固定高度诚实。
代价
每天都长这个样，卡片高度随内容浮动。如果你要首屏稳定，可以给一个 min-height，但那等于回到"撑场面"。

C · 单品类

唯一该给大面积的一类
为什么这一类配得上面积
单品图是高密度视觉——材质、版型、厚度、垂感全在图里，放大会看到更多东西。这不是撑场面，是内容本身需要。
但前提是真实素材
虚线框是故意留空的。我现在拿不出真实单品图，所以不画假的填满它——那正是上一版犯的错。
素材从哪来
① 用户衣橱自己的照片（WardrobeItem.media，零授权问题）；② 编辑图 / 授权图库；③ 生成图（按需，带 source_kind=generated_preview）。
素材决定节奏
素材到位前，日常主力是 A / B 这类排版驱动；C 只在确实有图时才出现。
这一条要诚实面对：没有真实素材，就不要假装自己有视觉。 排版驱动能做出好设计，假图撑面积做不出来。
