发型设计页 · 4 个方向 v2

去掉拟物隐喻，回到真实任务：我的照片 → 选一个发型 → 看效果 → 决定留不留。四个方向分别用「尺度、并置、流程、极简」四种真实排版手段做突破。照片为占位剪影，文案为示意。

A · 大字方向条（名字本身就是控件）

  • 不做卡片、不做图标：三个发型名就是横滑的巨型标题（选中 44px 加苔绿下划线，未选中 34px 灰），滑到哪个就是哪个。
  • 照片占上半屏，名字条紧贴图下，说明一行跟在后面随选中变化——视线只有「图 → 名字 → 动作」三步。
  • 结果态沿用同一条大字条换方向，底部两个动作：保存 / 换个方向。
  • 突破点：排版尺度当交互，控件消失；风险：长名字需截断，滑动力度要明确（有箭头提示更稳）。

B · 并置对比（现在 / 预览 同屏）

  • 把「长按看原图」改成并排同屏：左半「现在」、右半「预览」，中缝有可拖手柄——现实里换发型就是前后并排看，不靠记忆。
  • 方向选择降级为底部一排小 pill（直白字，选中反白），不再抢照片的位置。
  • 选方向态右半是占位（虚位以待），结构上预告「这一步会发生什么」。
  • 突破点：对比从交互技巧变成布局本身；风险：半屏照片偏窄，全身/长发细节会被裁，需定 aspectFit 与可放大方案。

C · 三步流程（01 你的照片 / 02 选方向 / 03 效果）

  • 整页是一条编号流程：01 照片 → 02 方向（三选一，选中墨底反白）→ 03 效果（未生成时是虚线空位）。用户永远知道自己在第几步、下一步是什么。
  • 左侧巨型编号（01/02/03）当导航锚点，右侧是内容，纵向网格，无卡片圆角。
  • 结果态 03 填成预览图，02 可回头换方向。
  • 突破点：用流程结构组织信息，最直白、最不俗；风险：一屏装三步需要收紧照片高度（01 的照片可缩到 190px）。

D · 沉浸单行（照片满屏，所有控件压在一行）

  • 照片出血到顶到底，页面上只有一个控件条：方向名 + ‹ › 切换 + 动作键，全部压在底部一条浮条里。
  • 方向名上方一行小字是当前效果说明；结果态多两个胶囊动作（看原样 / 换一个）。
  • 没有卡片、没有列表、没有装饰——决策面积全部让给照片。
  • 突破点：控件密度压到极限，最像「看照片」而不是「填表单」；风险：一次只看到一个方向名，需要 ‹ › 明确可滑可点。
