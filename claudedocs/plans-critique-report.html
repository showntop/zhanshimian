01专属性判定

品类通用。卡堆是被深度创作的：宝丽来纸堆、苔绿「喜欢」印章、6°/-9° 落卡、奶油渐变、纸屑、5s/7s/9s 质数浮动。结算屏把这些全扔了——这一屏可以原封不动换成任何左滑类 App 的结果页。创作系统在上游存在，但没有活到结果态。

峰终定律：此屏是「上传 → 等 1–2 分钟 → 滑完 N 张」的终点。峰值（看到自己脸的新效果图）在滑卡时已发生，终点却是清单式弱终点。终点应重演峰值，而非盘点峰值。

03优先问题

P0

1 喜欢场景的虚空

~60% 视口空白，下半屏没有构图锚点——读作「没做完」而非「留白」。

修法　liked ≤ 2 时，首张喜欢方案渲染为全宽「成衣卡」：复用 renderCard 的 veil + meta 构图，点击进详情；缩略条降级为 2+ 喜欢时的胶片条；底部虚空用纸堆 / 纸屑母题收边。

P1

主行动是三级视觉

「生成新的一轮」是全屏最重要的前进动作，却是 26rpx 居中文字链。

修法　升为苔绿全宽按钮，钉在 tab 栏上方；往期降为次级链接。（流向待定：重新生成 vs 每日线 vs 执行清单——先 shape 再动。）

P1

最后一张卡无法撤销

结果屏不暴露 undo，误滑不可逆；stack.history 现成。

修法　结果落定初期给一条紧凑「撤销上一决定」。

P2

往期入口重复

进度行 + 结果体各一个「往期 N ›」，增加的是回忆负载而非识别。

修法　ended 态只留结果体一处。

P2

字阶过平

标题 / 组头 / 链接全部落在 12rpx 区间，没有主导层级。

修法　标题 ~44rpx + 宋体数字母题；组头 26rpx；链接 24rpx ink-3——三层梯。组头 ♥ 补苔绿色（遵守「喜欢 = 苔绿」规则）。

04做得好的

  • 失败处理是被创作的：逐套重试 chip、带计数批量重试、failed / unavailable 分文案
  • 状态感知文案：生成中改口「上一轮」、防重复提交、制作中提示去重
  • 组头常驻计数：跳过收着也知道有几个

05人物红旗

  • 首次使用者：带着最高投入度离场，却没有「已保存、明天回来」的留存钩子
  • 回访用户：历史被表述为计数而非资产，积累轮次零视觉存在
  • 场合用户：结算不说「喜欢了之后去哪」（执行清单 / Brief 出口缺失）

06次要观察

  • 结果区唯一动画是通用 fade-up——结果屏比加载屏还少动画
  • __result 右 padding 仅 8rpx，首张缩略图贴边比任何内容都狠
  • 组头 ♥ 未用苔绿，违反 SCSS 头注规则

07检测器（B）

  • planning：1 warning——index.scss:145 transition:width（进度条惯例；可改 transform: scaleX）
  • daily：0 findings
  • 浏览器可视化：小程序不可跑，已记录跳过

08值得争论的问题

如果卡堆是「裁缝桌上的卡」，结算该是什么？喜欢的卡被叠好、包好、放到你面前——现在的清单还成立吗？

「生成新的一轮」真的是主 CTA 吗，还是该导向每日线（留存）或执行清单（价值）？

0 喜欢场景要不要专属构图？「没留下」是诚实的裁缝店节拍，还是读起来像产品故障？
